# Autarco Local v0.7.0 — Scenario & Configuration Logic

v0.7.0 turns Autarco Local from a register-oriented settings view into a scenario-first configuration layer while keeping the proven v0.6.6 safety model intact.

## Design goals

- Keep **Autarco Local** as the user-facing product and device identity.
- Use mature Solis Modbus patterns as a technical and UX reference for hybrid-inverter settings, dependencies, grouped register knowledge, diagnostics and future EMS control.
- Never assume that a Solis-supported write is automatically safe on Autarco hardware.
- Keep physical writes behind local Autarco validation, read-back, rollback and user confirmation.
- Separate brand-neutral energy logic from Home Assistant so the same logic can later be reused by `sns-ems-platform`.

## New in 0.7.0

### Scenario-first UX

The Settings page now starts with recognizable operating scenarios:

- Normaal zelfgebruik
- Accu vasthouden
- Nu laden vanaf het net
- Nacht-/tijdladen
- Maximaal terugleveren
- Peak shaving
- Backupreserve
- Onderhoud / battery healing

Scenario cards show whether their current underlying mode is detected and whether the scenario is guided, pending hardware validation, or not yet mapped. A scenario can highlight and open its related settings.

### Linked settings

Settings that influence other settings are marked with `🔗 Gekoppeld`. v0.7.0 adds a configuration-health summary above the raw setting groups.

The first hard cross-setting safety rule is:

- `Reserve SOC >= Minimum SOC`

A physical write is blocked when this proven relationship is violated.

Additional relationships are currently advisory, including work-mode coupling, inactive Time-of-Use values and Force-charge/Minimum-SOC overlap.

### Brand-neutral energy logic

`energy_logic.py` has no Home Assistant or Modbus transport dependencies. It:

1. normalizes validated holding registers into canonical energy settings;
2. evaluates cross-setting relationships;
3. derives configuration health;
4. derives scenario state/readiness;
5. exposes EMS capability names for later reuse.

This is the first reusable part of the future Local Energy / SNS EMS device layer.

### Device profile

`device_profile.py` formalizes the currently known Autarco S2.LH-MII register groups and categorizes them as fast, normal or slow data. The existing proven v0.6.6 poller remains active in 0.7.0; the profile is the safe basis for a later grouped/multi-cadence poller after hardware regression testing.

### Diagnostics

Home Assistant diagnostics now include:

- Autarco device profile;
- normalized settings;
- configuration health and findings;
- scenario evaluation;
- runtime registers;
- holding-register settings snapshot.

## Write safety

v0.7.0 intentionally does **not** unlock generic scenario writes. The hardware-validated Off-grid minimum SOC transaction remains the only physical settings write path. It now also passes through the new cross-setting configuration guard.

Future scenario writes must implement the same transaction pattern:

1. fresh pre-read;
2. validate all linked settings and safety prerequisites;
3. snapshot the complete affected mode/register state;
4. apply only the minimum required changes;
5. read back and verify;
6. stop on unexpected external state changes;
7. restore temporary state;
8. verify the restore;
9. expose the transaction in diagnostics.

## Solis Modbus reference policy

Solis Modbus is used as a reference implementation and knowledge source for architecture and UX patterns. Autarco Local keeps its own naming, validation model, UI and hardware qualification. No Solis branding is exposed as the primary user-facing integration identity.
