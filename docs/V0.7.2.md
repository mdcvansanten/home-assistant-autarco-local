# Autarco Local v0.7.2 — App dashboard, history and Time-of-Use UX

v0.7.2 turns the existing engineering dashboard into a first app-style user interface while preserving the proven v0.6.6 write baseline and the v0.7.0/v0.7.1 scenario, diagnostics and safety layers.

## Live energy-flow dashboard

The Overview tab becomes the primary live app screen. It shows PV, inverter, house load, battery and grid as one energy-flow diagram with live values, battery SOC, connection state and a compact day/status summary.

Battery and grid links remain visually bidirectional. v0.7.2 deliberately does not claim charge/import/export direction from an unvalidated sign convention. Direction semantics can be tightened after field validation.

## History

A new History tab reads Home Assistant Recorder history for any Autarco Local entity. The first implementation supports 6 hour, 24 hour and 7 day views and intentionally reuses Home Assistant storage instead of creating a second database.

The next history iteration should use Home Assistant long-term statistics for month/year/custom ranges so large historical datasets remain efficient.

## Solis-inspired Time-of-Use planner

The Settings page keeps the existing scenario-first structure, safety colours, relation checks and PIN/write protection. Time-of-Use presentation is reorganised as a planner:

- Time-of-Use mode and scheduled charge/discharge current are grouped together;
- charge/discharge times are presented as periods instead of sixteen unrelated rows;
- unused periods stay hidden;
- users can reveal another period with `+ Tijdslot toevoegen`;
- configured periods remain visible automatically;
- charge and discharge settings are visually paired per period.

This change is presentation-only. It does **not** unlock Time-of-Use writes. Physical writes remain blocked until register mapping, dependencies, conflict handling and read-back are validated on the live Autarco hardware.

## What remains unchanged

- scenario engine and scenario-first settings flow;
- green/yellow/red safety classification;
- validated Off-grid Minimum SOC write path;
- installer/system settings stay protected/read-only;
- deep Wi-Fi/TCP 502/Modbus diagnostics introduced during v0.7.1 field testing.

## Next phase, not v0.7.2

A brand-neutral hardware/device adapter layer remains the intended next architectural step after the current Autarco experience has crystallised. SNS EMS should consume canonical capabilities rather than Autarco/Solis register numbers. v0.7.2 deliberately focuses on making the current Autarco Local app complete and usable first.
